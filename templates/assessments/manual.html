{% if is_staff %}Chapter 1{% else %}Candidate Guide{% endif %} Preparation & Testing Workspace

Candidate Testing & Preparation Guide

Everything you need to know about preparing your workstation, passing device diagnostics, and navigating the live test workspace.

1.1 Hardware & Environment Requirements

To ensure a seamless assessment session without technical interruptions, verify the following prerequisites on your computer:

Supported Browsers

Google Chrome (v90+), Microsoft Edge (v90+), or Firefox. Mobile browsers are not supported.

Webcam & Lighting

Functional front-facing webcam with adequate room lighting. Avoid bright backlights.

Internet Connectivity

Reliable broadband connection (≥ 1.0 Mbps download & upload) to ensure uninterrupted real-time code auto-save.

Quiet Testing Space

A private room without secondary monitors, mobile devices, notes, or third-party individuals.

1.2 The 3-Step Candidate Pre-Flight Flow

The platform guides candidates through a structured, transparent pre-flight flow prior to starting:

1
Step 1: Identity & Profile Verification

Confirm your full legal name, phone number, and upload your latest PDF resume. This profile is used by recruiters during interview stages.

2
Step 2: Assessment Briefing & Rules

Inspect section allocations, time limits, special instructor notes, and accept the Code of Conduct honor code.

3
Step 3: Live Device Diagnostics Gate

Perform a live hardware test verifying webcam centering, network latency, geolocation sync, and lock into full-screen mode before the test timer begins.

1.3 Workspace Navigation & Section Timers

During your assessment, keep the following workflow rules in mind:

Section Timers vs. Total Timer

Each section has its own countdown timer. When a section timer expires, answers in that section are saved and you transition to the next section automatically.

Question Palette Navigation

Use the palette chips at the top to jump between questions. Green dots signify answered items; gray items are unattempted.

1.4 Live Coding Workspace & Test Execution

For coding challenges, the workspace provides an integrated Monaco code editor:

Run Code: Executes your solution against sample public test cases to inspect stdout/stderr without consuming your final submission.
Submit Solution: Submits your code to run against both public and hidden grading test cases to calculate your final algorithm score.
Auto-Save: Code drafts are synced automatically every few seconds. If you accidentally reload, your latest code is restored.

1.5 Conduct & Proctoring Rules

Fullscreen Mode Required

Departing full-screen or switching windows logs a tab-switch event in your review audit. Always stay focused on the assessment tab.

Webcam Centering

Keep your face clearly illuminated and visible inside the preview frame throughout the entire session.

Independent Work

External notes, unauthorized aids, secondary monitors, and third-party collaboration are strictly prohibited.

1.6 Technical Support, Network Drops & FAQs

What happens if I accidentally switch tabs or minimize my browser? ▾

Departing full-screen or switching to another window logs a tab-switch event in your reviewer telemetry report. The system allows a configurable tolerance (e.g. 3 switches for unintentional notifications). Exceeding this limit flags your attempt for manual administrator review.

What happens if my internet connection drops during the assessment? ▾

The platform includes an automated local storage fallback. Keystrokes, MCQ selections, and code drafts are continuously cached in your browser. When connectivity is restored, all responses synchronize with the server automatically.

Chapter 2 Authoring & Configuration

Test Authoring & Question Pool

How to configure test parameters, organize sequenced sections, author MCQ questions, and set up automated coding challenge test cases.

2.1 Creating an Assessment

From the staff dashboard, navigate to Create Assessment (/staff/exams/new/). Specify:

  • Assessment Title & Slug: Clear title and URL identifier.
  • Scheduled Availability Window: Specific open and close dates/times when candidates can access the exam.
  • Duration & Buffer Time: Total active minutes allowed once the candidate enters the diagnostic room.
  • Integrity Thresholds: Enforce full screen, webcam monitoring, face absence limits, and tab-switch maximums.

2.2 Sections & Multi-Format Assessments

Assessments can be divided into distinct, timed sections (e.g. Section 1: Core Aptitude [20m] → Section 2: Python Algorithms [45m]). Each section can have its own independent timer that submits upon expiration before moving to the next.

2.3 Coding Challenge Execution & Test Cases

Coding problems support Python, Java, JavaScript, C++, C#, Go, and Rust. For each problem, instructors can supply:

Public Sample Test Cases

Visible to candidates in the code playground to test their algorithms and view stdin/stdout outputs.

Hidden Grading Test Cases

Evaluated securely upon submission to verify edge cases, time limits, and memory complexity.

Chapter 3 Candidate Operations

Candidate Enrollment & Credential Delivery

Register candidates individually, import bulk CSV files from recruitment spreadsheets, and dispatch secure access credentials.

3.1 Standard CSV Import Format

When uploading cohorts via the Bulk Import tool, format your file as a standard UTF-8 encoded CSV:

email,full_name,phone

3.2 Automatic Password Generation & Dispatch

Upon enrollment, high-entropy random passwords are created. Click Send Credentials on the candidate roster to dispatch invitation emails containing unique login credentials and direct testing links.

Chapter 4 Proctoring & Review

Live Proctoring, Telemetry & Audit Logs

Monitor active exam attempts, review automated integrity flags, and inspect post-assessment audit trails.

4.1 The Reviewer Audit Interface

Opening a candidate attempt (/staff/attempts/<id>/review/) displays the full evaluation timeline:

Timeline of Events

Chronological feed of tab-switches, window blurs, full-screen exits, and device disconnects.

Proctoring Snapshots

Camera frames captured strictly during anomaly events to confirm whether candidate remained at desk.

Code Replay & Diff

Playback candidate keystrokes and code diff evolutions to spot large sudden paste actions.

Chapter 5 Interviews & AI Assistance

Multi-Round Interviewing & AI Copilot

Conduct live coding interviews, evaluate candidate competencies, and utilize AI assistance for question generation.

5.1 AI API Keys & Model Routing

Under AI Keys (/staff/ai-keys/), configure provider keys (Gemini 2.5 Flash, OpenAI GPT-4o, Anthropic Claude 3.5). The system automatically tracks usage counters, handles rate-limit backoffs, and balances load across multiple active keys.

Chapter 6 Administration & RBAC

Staff Administration & System Settings

Manage organization branding, SMTP mailer credentials, and granular staff role permissions.

6.1 White-Label Branding & Contact URLs

In Settings (/staff/settings/), configure your organization's display name, logo mark, candidate support email, and emergency contact phone.

6.2 Email Notification Transport (SMTP)

Configure your company SMTP server (e.g. Amazon SES, SendGrid, Mailgun, or corporate Exchange) to deliver candidate invitations. Supported protocols include STARTTLS (port 587) and SSL/TLS (port 465). Use the built-in Send test email tool on the settings screen to verify connectivity.

6.3 Role-Based Access Control (RBAC)

Manage your recruitment team in Team Roles (/staff/team/). Granular capabilities include:

exams.manage: Create and edit assessments
exams.publish: Publish or unpublish tests
candidates.manage: Enroll and invite candidates
results.review: Evaluate code and proctoring telemetry
team.manage: Provision staff accounts and roles
settings.manage: Configure platform settings and SMTP
